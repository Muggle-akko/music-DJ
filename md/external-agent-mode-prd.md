# Awudio 外部 Agent 模式：供开发 Agent 执行的 PRD

状态：首版工程实现已接入，待验收。按用户要求暂不进行验收测试；M3 的真实客户端/播放验收尚未完成。见 [接入与实施说明](external-agent-setup.md)。
日期：2026-10-16。审查基线：`d695c2d`，本地单用户项目。

## 1. 产品决策

新增“外部 Agent”模式。用户在 Codex 等电脑端 Agent 软件中交流，外部 Agent 负责理解上下文、澄清音乐人身份、调用音乐工具、选择和编排歌曲；Awudio 负责曲库访问、结果校验、展示、播放、状态同步及反馈持久化。

```text
用户 ↔ 外部 Agent 的聊天窗口
              ↕ MCP
         Awudio 音乐工具服务
              ↕
  网易云适配 / 收藏与反馈 / 播放资格 / 计划与命令
              ↕
        Awudio 网页播放器
```

外部 Agent 模式的音乐工具路径不得再调用内置 DeepSeek/OpenAI 规划、选曲或聊天接口。外部 Agent 自身可能使用云端模型，其模型费用、额度和可用性由所使用的客户端决定；不能称作“完全离线”或“免费本地推理”。

这是既有模式之外的新入口。根据后续用户决定，内置推荐 V1 移除，V2 继续独立使用；不在本轮同时重写内置聊天。

## 2. 问题与目标

当前 V2 已有真实候选召回、资格检查和反馈机制，但对话入口仍受固定流程限制：默认推荐、推荐规划缺少完整对话、音乐人识别过度依赖精确拼写。

本轮利用外部 Agent 已有的对话和工具循环，解决三件事：

1. 用户可以正常聊天，只有出现选歌任务时才检索、推荐或播放。
2. 可以查资料、比较同名音乐人，并在必要时追问；追问后接着完成原任务。
3. 推荐结果可靠地到达播放器；播放是否成功以浏览器反馈为准。

成功不是“接通 MCP”或“调用工具很多次”，而是用户在 Agent 中说出需求后，能得到符合意图的真实歌曲，并准确控制本地播放。

## 3. 已有能力与必须新增的边界

下表来自上述代码基线；具体实现前再次核对当前代码。文件中存在函数不等于已完成本轮联调。

| 当前能力 | 本轮处理 |
|---|---|
| `lib/ncm.mjs`：网易云 HTTP 与业务状态检查 | 复用；凭证留在服务端 |
| `lib/taste/*`：账号画像、事件、学习摘要 | 复用；对 Agent 返回受限摘要与分页结果 |
| `lib/recommendation/playability.mjs`：完整/试听/受限/未知 | 复用；提交和实际播放时检查 |
| `lib/recommendation/tools.mjs`：V2 内部受限召回 | 可提取共享适配；不能直接沿用精确字符串即唯一实体的判断 |
| `lib/recommendation/orchestrator.mjs`：固定规划与选曲流程 | 外部模式不进入此模型编排；可复用独立的确定性过滤函数 |
| `GET/POST /api/queue`：队列持久化与 revision | 现有写入没有完整 CAS；本轮须补冲突保护及浏览器同步 |

| `public/app.js`：浏览器播放与队列本地副本 | 新增外部计划展示、同步和命令消费，不能仅改服务端 JSON |
| `public/listening.mjs`：实际收听事件 | 继续由实际播放触发；提交歌单不能产生收听事件 |
| `lib/storage.mjs`：串行与原子写入 | 复用，保证计划应用、revision 和幂等记录的一致性 |

## 4. 范围与实施顺序

### 4.1 P0：首次可用版本，必须全部完成

- 本地 MCP 服务及 Codex 接入说明、专用音乐 Skill。
- 真实音乐人搜索与详情、歌曲搜索、音乐人歌曲、相似歌曲、收藏查询、播放资格查询。
- Agent 可提交带来源和说明的候选计划，在网页显示。
- 支持应用计划到队列，以及播放、暂停、上一首、下一首。
- 浏览器连接状态、明确的播放设备选择、命令回执和冲突保护。
- 复用现有收听与明确反馈，保存外部计划的归因。
- 真实网易云、Codex、浏览器端到端验收。

### 4.2 P1：P0 验收后另行推进

日推、歌单搜索和歌单曲目 MCP 工具；更完整的阶段编排 UI；第二种 Agent 客户端的实测适配；多客户端接力优化。

### 4.3 本轮排除

整套引入 ZCode/DeepSeek Harness；自建通用 Agent 平台；网页反向驱动桌面聊天软件；模拟键鼠或修改播放器源码来日常选歌；后台自动唤醒 Agent；自动补歌；手机远程访问、云部署、多用户、离线下载、真实音频理解。

用户没有授权修改网易云红心、删除云端歌单等账号写操作，本轮不提供这些工具。

## 5. 对话与执行契约

### 5.1 不同用户表达的行为

| 输入 / 状态 | 应有行为 |
|---|---|
| “早上好” | 外部 Agent 正常回应；不因问候检索、提交或播放歌曲 |
| “聊聊 Bôa” | 回答或查资料，不自动生成歌曲卡片 |
| “我想听 boa”且缺少消歧上下文 | 搜索音乐人，必要时比较详情；存在实质歧义时列出简短选项并询问 |
| “英国乐队 boa” | 用地域、乐队属性等证据识别；足够明确时直接继续，不机械重复确认 |
| 追问后用户回答“英国那个 / 第二个” | 继续原听歌任务；不能把这一句独立当作推荐关键词 |
| “推荐三首他们的歌，先别放” | 提交展示计划；不修改队列、不播放 |
| “加入队列” | 追加明确选中的计划；保持当前正在播放的曲目 |
| “播放刚才那三首” | 应用对应计划并请求播放，无须再问一次相同许可 |
| “换一整期，别打断这首” | 替换待播部分，保留当前音频与播放位置 |
| “下一首 / 暂停” | 直接控制选中的播放器，不重新推荐 |
| “为什么选这首” | 根据已存推荐依据回答；不能编造曲风或收听经历 |

外部 Agent 决定是否调用工具；音乐 Skill 明确以上行为。后端还必须独立验证写操作的权限、参数、状态与可播放性。后端不能仅凭 Agent 提交一句“用户已同意”就宣称技术上证明了用户意图。

### 5.2 音乐人解析

搜索时支持大小写、Unicode、重音折叠和别名等候选扩展；`boa` 可以召回 `Bôa`，不能据此把不同音乐人合并。

`search_artists` 返回多个真实候选及可用区分信息，不在服务端按“第一个结果”或“拼写最精确”替用户作最终选择。Agent 必要时调用详情工具，根据国别、乐队/个人、简介、代表作、对话约束判断。

只返回可核查的信息；上游没有国别或简介时标记未知。可增加有上限的兼容检索；不能仅靠模型记忆伪造网易云 ID 或音乐人属性。

确认后用真实 `artistId` 查询曲目，并校验曲目实际关联该音乐人。音乐人查询失败或尚未消歧时，不用其他收藏补成看似成功的专题。

### 5.3 对话记忆与音乐记忆

- 完整聊天、追问与候选选择由外部 Agent 会话承载。
- 跨客户端共享的收藏、反馈、收听记录、计划和实际队列由 Awudio 保存。
- 默认不把完整外部聊天记录复制到音乐服务；提交计划只附本次相关需求摘要及已确认约束。
- Agent 换会话时先读取音乐上下文；不能假装记得另一软件未共享的聊天。
- Agent 选择与理由应可展示，不要求提供隐藏推理过程。

## 6. MCP 与服务结构

### 6.1 首选接法

P0 使用本地 STDIO MCP 桥接进程，连接既有 Awudio Node 服务。桥接进程负责 MCP schema 和结果适配；音乐业务、账号隔离、持久化及命令校验集中在 Awudio 服务，避免桥接进程和主服务同时直接写同一状态文件。

外部 Agent → MCP 工具 → 本地服务新增受保护接口 → 共享业务服务。

不得使用“Agent 执行 curl + 手动改 JSON 文件”作为正式接入方式。开发时可以使用命令行诊断。

MCP 启动方式、依赖版本、连接配置须在实施时按客户端官方文档验证。只安装必要 MCP SDK；不引入额外 Agent 框架或插件市场。WorkBuddy 尚未验证，不能写成已兼容。

### 6.2 本地访问边界

- Agent 专用 HTTP 接口只接受本机访问及本地桥接凭证；不能因名字包含 `/agent` 就默认安全。
- 若现有网页继续监听通配地址，Agent 接口也必须校验实际对端及认证，不能随网页一起无保护暴露。
- 浏览器控制接口校验同源与当前播放设备会话；外部站点不能借请求触发播放或替换队列。
- 桥接凭证由本地配置读取，不进入模型工具参数、页面文本、URL 查询字符串或日志。网易云 Cookie、AI Key 更不能返回 Agent。
- 工具只允许固定业务动作，不接受任意 URL、脚本、文件路径或账号选择参数。
- 当前账号由服务端决定。切换账号须使旧桥接会话、候选、计划和待执行命令失效，重新获取上下文。

### 6.3 业务服务划分建议

建议新增 `lib/agent/`：context/catalog/plans/player-commands/events，以及独立 MCP 入口和音乐 Skill。具体文件名可按现有代码调整。

不要为兼容 MCP 复制一份 NCM、播放资格、学习或存储逻辑。现有内部工具若与 V2 生命周期耦合，先提取可测试的共享业务服务，再供 V2 和 MCP 适配调用。

## 7. P0 工具契约

以下是拟新增工具名，不代表当前存在。最终每个工具必须有严格输入 schema、长度和分页边界，并标明只读或有副作用。

| 工具 | 核心输入 | 输出 / 边界 |
|---|---|---|
| `awudio_get_context` | 无，可带结果上限 | 连接状态、模式、设备、实时状态新鲜度、queueRevision、最多 20 首队列摘要、最多 20 条近期摘要、画像覆盖率；不返回整库 |
| `awudio_search_artists` | query ≤ 80 字、limit ≤ 10 | 多个真实 ID、名称、别名、简介摘要与来源；不擅自唯一化 |
| `awudio_get_artist` | artistId | 真实详情与区分线索；不存在返回 not_found |
| `awudio_search_tracks` | query ≤ 80 字、cursor、limit ≤ 50 | 歌曲、音乐人 ID、专辑、时长、版本与来源 |
| `awudio_artist_tracks` | artistId、cursor、limit ≤ 50 | 验证音乐人后返回关联歌曲；ID 不存在须明确失败 |
| `awudio_similar_tracks` | trackId、limit ≤ 30 | 原始种子、真实关联歌曲及来源 |
| `awudio_library_lookup` | 受限过滤、cursor、limit ≤ 50 | 收藏/可靠反馈候选及覆盖说明，不暴露邮箱等无关账号资料 |
| `awudio_check_playability` | 最多 30 个 trackId | 逐 ID 返回 full/preview/blocked/unknown、checkedAt；不返回原始签名音频 URL |
| `awudio_submit_plan` | 见 8.1 | 验证并保存展示计划；不修改队列或播放；返回 planId、有效曲目与不足说明 |
| `awudio_apply_plan` | planId、operationId、expectedRevision、queueMode、playback、targetPlayerId | 原子应用队列并创建所需播放器命令；返回保存与执行状态，不提前报告已播放 |
| `awudio_control_player` | operationId、targetPlayerId、action、expectedPlaybackSessionId、expectedRevision（按动作要求） | play/pause/next/previous；对过期目标返回冲突，不执行到另一首上 |
| `awudio_get_operation` | operationId、waitMs ≤ 5000 | 查询或短等执行结果，给出最新状态；不用高频无限轮询 |
| `awudio_record_feedback` | operationId、trackId、action、planId?、undoOf? | 本地 like/unlike/dislike/undo_dislike/not_now/undo_not_now；与既有事件语义一致，幂等 |

所有音乐 ID 使用字符串。工具返回 `schemaVersion`、`status`、数据或错误、必要的来源与时间戳。MCP 协议错误、业务失败和空结果须区分；不能把 HTTP 200 或 MCP 调用完成当作业务成功。

公共业务状态包括：ok、empty、not_found、unauthorized、rate_limited、timeout、unavailable、conflict、invalid_input。播放另有第 9 节的执行状态。

工具结果要足够让 Agent 自行比较和选择，不能只有“调用现有推荐器”的黑盒接口。所有元数据和歌单简介都是不可信内容，不得被当成工具指令。

## 8. 推荐计划与确定性校验

### 8.1 提交示例

```json
{
  "operationId": "客户端生成的唯一操作ID",
  "requestSummary": "推荐英国乐队 Bôa 的三首歌曲，先展示",
  "intent": "recommend",
  "confirmedArtists": [{"artistId": "上游真实ID", "name": "Bôa"}],
  "constraints": [{"field": "artistId", "operator": "in", "value": ["上游真实ID"]}],
  "tracks": [
    {
      "trackId": "已检索的真实ID",
      "lookupRef": "服务端返回的检索证据引用",
      "stageId": "main",
      "reason": "本次选曲理由，最多200字",
      "evidenceRefs": ["可引用的实际证据ID"]
    }
  ],
  "stages": [{"id": "main", "label": "Bôa 专场"}]
}
```

示例是结构说明，不得把占位字符串当成真实 ID。单次计划 1–30 首、需求摘要 ≤ 1000 字、阶段 ≤ 6 个。不得把 Cookie、模型 Key、完整对话或任意音频 URL 填入提交内容。

服务端必须：

1. 校验 ID 与账号边界，并从共享曲库服务重取或读取可信缓存中的曲目元数据。以服务端元数据为准，忽略 Agent 伪造的标题、时长和 URL。
2. 核验 lookupRef 与该次桥接会话、曲目及可引用事实的关联；客户端提供的“证据”不能自我认证。检索凭据初始 TTL 为 30 分钟，过期要求重新查询。
3. 过滤重复 ID、明确屏蔽、音乐人/版本等可核查约束和非完整可播曲目。未知不能冒充满足严格条件。
4. 同时保存 Agent 原始选择与最终接受列表、拒绝原因；不重跑模型、不静默加歌或重排 Agent 顺序。
5. 返回实际首数、总时长、缺口与解释。没有合格曲目时不创建可执行计划。
6. 理由只能引用已有事实或明确标记的主观选择；服务端能校验证据存在及关联，不声称能完全证明自然语言理由。

### 8.2 应用计划

队列模式：`append`、`replace_all`、`replace_upcoming`。播放行为：`keep`、`play_first`，两者独立。

- `append + keep` 只追加，保持当前音频和位置，不自动播放。
- `replace_upcoming + keep` 保留当前曲目、音频与位置，只替换待播部分。
- `replace_all + play_first` 对应明确的整期替换并开始播放。
- `replace_all + keep` 仅允许当前没有加载音频的情况，否则返回冲突并提示选择保留当前或明确开始新计划。
- 队列总上限沿用 200，超限返回不足/冲突，不能静默挤掉已有歌曲。
- 在应用前重新检查有时效的播放资格。若接受列表改变，返回 plan_changed 与差异，由 Agent 结合原请求说明并重新提交；不悄悄用其他歌曲替代。

plan 默认可应用 30 分钟，服务重启后仍可读取；实际资格以应用和播放时为准。计划可读保留 30 天，与已有推荐记录保留策略一致。

## 9. 网页同步、设备与播放回执

### 9.1 连接与实际状态

新增网页中的模式选择：内置推荐 / 外部 Agent。内置推荐统一 V2，不再保留 V1/V2 切换。

外部模式显示 MCP 最近活动时间、已登记的 Agent 客户端名称和播放器状态。名称是客户端声明，不是已认证的软件品牌；只有当前活跃连接才显示在线，不保证 Agent 正在思考或可被主动唤醒。

网页显示当前播放设备，首次只有一个活跃页面时可自动选择。多标签页每个有不同 playerId，单个账号同时只允许一个页面持有外部控制租约；其他页面仅同步展示，不执行音频命令。

采用服务端事件流同步计划/队列/命令，浏览器通过同源请求上传心跳、audio 状态和回执。若选 SSE，必须处理事件序号、断线重连和快照恢复；不能仅依赖一次通知。Agent 使用 STDIO MCP，无需直接连接浏览器。

初始参数集中配置：心跳 5 秒、15 秒未更新标记离线、控制租约 20 秒且心跳续租、命令有效期 15 秒。后台节流可能导致离线判定，UI 应如实显示，不能延长旧命令直至突然播放。命令携带租约代次，旧页面恢复不能继续执行旧代次。

实时状态包含 trackId、playbackSessionId、paused、positionMs、durationMs、lastSeenAt、queueRevision。`/api/now` 的历史记录不能替代这些字段。

### 9.2 命令生命周期

`accepted → delivered → applied / needs_user_gesture / failed / expired / uncertain`。

- 保存计划只返回“已展示”；保存队列只返回“队列已更新”。
- 浏览器确认 audio 已进入 playing 才报告“已开始播放”；play Promise 成功但尚在缓冲时仍处于等待状态。
- 自动播放被浏览器阻止时返回 `needs_user_gesture`，网页给“点击开始播放”入口，Agent 如实说明。
- 未打开网页、目标离线或未选择设备时，允许保存展示计划；播放请求返回 unavailable，不留下会在日后突然执行的播放指令。
- 15 秒内没有确认则命令过期或状态不确定；迟到回执保留审计并重新核对实际状态，不改写成确定失败后自动重发。
- 已送达后取消、页面崩溃或回执丢失可能无法证明是否执行。标记 uncertain，先读取实际状态，不能承诺跨崩溃“严格执行一次”，尤其不能盲重试 next/previous。
- 模型会话结束、MCP 断开不影响已建立队列的正常连续播放。默认不自动唤醒 Agent 补歌。

## 10. 并发、幂等与用户控制优先

1. 所有新增写工具使用 operationId，并将参数摘要、结果与业务修改一致地持久化。同账号相同 ID 相同参数返回原结果；相同 ID 不同参数返回冲突。初始去重保留 7 天。
2. 所有队列写入路径共用串行 CAS：比较 expectedRevision 后再写入；冲突返回最新 revision 和摘要。现有网页写接口也须接入，不能留一条无条件写路径。
3. 网页有尚未提交的本地队列编辑时，先完成或合并本地变更，再处理外部快照；不得被旧快照覆盖，也不得把远端快照当成本地编辑重新回写形成循环。
4. 控制命令绑定目标 playerId、租约代次、预期 playbackSessionId；next/previous 同时校验队列 revision。发送后用户手动切歌时，旧命令不得作用于新曲。
5. 应用队列和生成命令须有一致的 operation 记录，重启可恢复与核对。浏览器执行前验证命令仍有效且队列 revision 已同步。
6. 退出外部模式立即终止租约并取消尚未执行的命令；保留已播放事实和已应用队列。Agent 后续写入返回 mode_inactive，不自动切回。
7. 网页已接受的新手动操作使冲突的旧外部动作失效；在途操作冲突必须展示，不能自动重试覆盖用户。
8. 若外部模式切换与内置推荐请求并发，取消或拒绝迟到的内置队列替换结果。

## 11. 反馈与记录

外部计划给每首歌保留 planId、stageId、来源、推荐理由、可引用证据、origin=external_agent。对已有 recommendationId 字段做显式兼容映射，不伪造一份 V2 模型 trace。

展示曝光、加入队列、实际播放和主观反馈分别记录。继续沿用有效收听时长规则；Agent 提交、命令接受和音频 URL 获取都不能记成已收听或喜欢。

删除队列不扣分，暂时不合适只影响场景，不喜欢屏蔽曲目，撤销保留对应 undoOf。明确反馈从网页或 MCP 写入同一事件服务；不能由两个入口重复学习一次。

日志记录工具调用时间、状态、候选 ID、计划变化、命令与回执、冲突及模型外部来源声明；不记录凭证、原始签名音频 URL、隐藏推理或整份个人资料。

预算初始值：每个工具调用总截止时间 10 秒，上游 5 秒；每个桥接会话最多 4 个并发读取；每分钟最多 60 次上游请求，分页和失败都计入。Agent 不得无限轮询，不足时展示已有结果或询问。预算只约束音乐服务，不宣称限制外部客户端全部模型调用。

## 12. 音乐 Skill 与接入交付

交付项目内可安装的音乐 Skill，说明：

- 先读 context；问候、介绍、明确推荐、播放控制的区别。
- 音乐人候选的查询、消歧、追问接续与真实 ID 绑定。
- 用工具检索、比较和选曲；禁止编造 ID、URL、音频理解及未测量特征。
- 提交展示与应用播放分离；不重复询问已明确的播放请求。
- 如何处理冲突、受限歌曲、自动播放阻止、离线和 uncertain。
- 验证 operation 回执后再用“已播放”；不要把“请求已接受”当完成。
- 不读取 `.env` 或通过修改数据文件绕过工具。

提供 Codex 的启动、连接、工具发现、停用及排障说明；优先项目范围配置。Skill 指导对话行为，工具定义本身也必须足够清晰；没有加载 Skill 时，服务端边界仍应有效。

文档写清：该模式从外部 Agent 发起操作，网页不会因勾选模式就获得唤醒 Codex 的能力。P0 不承诺在其他未验证客户端中开箱即用。

## 13. 分阶段任务与验收

### M1：音乐工具可用

实现共享业务服务、MCP、上下文、检索/详情/收藏/相似/资格查询、submit_plan，以及专用 Skill。网页可看到计划；即使未配置 AI Key，外部工具链也能工作。

### M2：网页控制闭环

实现模式、设备租约、事件流、CAS、apply_plan、control_player、回执与幂等；接回既有反馈和实际收听记录。同步更新 Service Worker 缓存，避免旧页面使用旧协议。

### M3：真实客户端验收与文档

在 Codex 中完成下表。测试需同时覆盖服务单元、隔离集成与实际浏览器；真实客户端未接通不能用手工 curl 或 mock 代替通过。遇到客户端接入限制，明确记录已完成层级与剩余条件。

| 场景 | 必须观察到的结果 |
|---|---|
| 问候、介绍音乐人 | 无推荐计划和队列副作用 |
| 单独输入 boa，检索中存在多个合理候选 | Agent 提问；未确认不播放 |
| 英国乐队 boa / 回答“英国那个” | 确认真实音乐人 ID，并连续完成原任务；无其他音乐人的混入 |
| 先推荐三首不播放 | 网页出现真实卡片，当前音频和队列保持原状态 |
| 播放刚才三首 | 正确应用顺序；浏览器实际 playing 后 Agent 才报告开始 |
| 当前歌播放中追加 / 替换待播 | 音频不重载、位置不中断，队列和服务端 revision 一致 |
| 浏览器自动播放阻止 | needs_user_gesture 与可点击恢复入口，不报告播放成功 |
| 网页关闭、休眠、断网、重连 | 离线状态准确；恢复后过期命令不补执行 |
| 两个网页同时打开 | 只有持租约页面发声；切换设备后旧页面不能执行新命令 |
| 手动编辑与外部写入并发 | 冲突可见，本地未保存编辑不丢；旧写入不能覆盖新队列 |
| 重复 operation、服务重启、回执丢失 | 不重复追加；next 不盲重试；不确定状态如实呈现 |
| 试听、受限、资格过期、上游超时 | 无假完整播放、假空结果或静默换歌 |
| Agent/MCP 退出，播放继续 | 已有队列正常切歌，没有额外模型调用 |
| 网页与 MCP 同时反馈、撤销 | 同一事件幂等，实际收听归因到外部计划 |
| 退出外部模式后迟到命令 | 拒绝执行，不自动切回模式 |
| 凭证/任意 URL/越界参数检查 | 私密字段不进入工具结果或日志；非法调用被拒绝 |

真实听感另行由用户验收，不能以工具调用成功推断推荐更好。记录实际耗时，不在未测量前承诺固定响应速度。

## 14. 交付与完成标准

开发 Agent 应交付代码、必要依赖与锁文件、项目内 Skill、接入与排障文档、协议说明、验收记录。保持运行数据忽略规则；不提交 Cookie、Key、桥接凭证、个人画像或实际收听数据。

完成汇报至少说明：实现了什么、如何连接与使用、哪些场景真实验证、哪些只做了 mock、仍有哪些限制。只有 M1–M3 的 P0 项均完成且 Codex 端到端可用，才能标记本 PRD 已实施。

本 PRD 对“外部 Agent”模式具有优先级；`recommendation-agent-prd.md` 继续描述内置 V2。不得因旧 PRD 的固定模型规划要求，在外部模式重新调用内置模型。
