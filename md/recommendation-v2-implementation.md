# 推荐 V2 实施与验收记录

日期：2026-10-16。状态：工程实现已接入，开放本地试用；连续收听与个人体验验收待完成。

## 已实现

- `lib/taste/profile-sync.mjs`：CLI/HTTP 共用的收藏同步，按账号隔离，分页覆盖率、部分失败保留快照、截断播放榜、歌曲级百科标签增量缓存。移除了把用户所有歌单名称附加到每首歌的推断。
- `lib/taste/events.mjs`、`learning.mjs`、`public/listening.mjs`：实际播放会话、唯一收听区间、暂停/拖动/缓冲处理、稳定 eventId 重试、乱序保护、明确反馈撤销、90 天原始事件轮转与衰减聚合。开始播放、队列删除不产生偏好分；取消喜欢不变成不喜欢。歌手/标签的推广需要至少三首独立曲目的正反馈证据。
- `lib/recommendation/`：统一候选池、真实 ID 与来源证据、硬约束、归一化打分、熟悉/探索软配额、歌手/专辑间隔、按实际时长分阶段、完整/试听/受限/未知资格和账号隔离缓存。
- 受限 Agent：规划检索 -> 执行白名单工具 -> 在最多 80 个真实候选里选 ID -> 程序校验与补位。允许一轮补查，最多四次模型调用（含一次 JSON 修复）、12 次检索，上游并发四个，默认推荐预算 30 秒。超时用执行器显式终止等待，不只依赖上游实现 AbortSignal。
- 模型与确定性内核共用候选；模型失败、来源超时、资格不足可分别降级。零首不清队列、不创建成功电台；不把演示曲目混入 V2。
- 真正播放后才更新 now-playing，生成结果保留独立推荐 ID；候选、分数、来源、校验、回退保存在本地 trace。队列与历史往返保留推荐归因。
- 状态增量更新通过串行 read-modify-write，生成时不持锁；旧快照写回保留并发队列/反馈。请求 ID、队列版本保护过期结果。
- 最小界面：试用开关、同步偏好与覆盖率；歌曲菜单“现在不合适 / 不喜欢 / 为什么推荐”，反馈可撤销；对话卡片可查看来源依据。曝光依据实际可见卡片记录，展示与播放分开。
- 继续使用已有播放器/TTS 接口。V2 明确请求解说时提供有证据的开场文字，语音按播放时懒加载；本次没有实现音频分析或丰富的创作背景解说。

## 如何使用

打开本地电台，在 AI 电台中勾选“试用新版推荐”。偏好已同步时无需每次重取。可以尝试：

- “只听熟歌，推荐 5 首，不要 Live。”
- “发现 5 首收藏之外的歌。”
- “来一期周杰伦的歌，包含《晴天》和《七里香》，5 首。”
- “写代码 10 分钟，然后放松 10 分钟。”

普通推荐只展示卡片；明确整期或点击生成歌单才替换队列。提到“歌单”作为来源不会自动替换队列。明确给出网易云歌单 ID 或链接时先验证歌单再取歌。

`RECOMMENDER_VERSION=v1|v2` 控制未选择过版本的客户端默认值；浏览器主动选择优先。按 PRD，当前 `.env.example` 默认 v1，V2 可直接试用，尚未默认推广。`RECOMMENDER_AGENT_RERANK=false` 只关闭模型重排，保留结构化规划与确定性选曲，便于对照。

已用当前账号实际同步 1,378 / 1,378 首收藏；历史榜、周榜各返回 100 条，均按截断样本保存。

已验证相似歌曲、日推、歌曲搜索、歌单搜索/内容、歌手搜索/热门歌曲、歌曲百科及批量 URL 资格；上游接口可能单轮超时或返回业务错误，trace 保留该轮来源状态。

已运行熟歌、探索、纯音乐/排除版本、指定歌手和歌曲、多阶段、未知/不足条件六类请求。实际联调中：

- DeepSeek 能选出真实候选 ID 并引用提供的证据，熟歌/探索请求可正常交付。
- 歌手实体精确匹配保留标点，修复“周杰伦”与“周杰伦.”被误判同名的问题；曾实际返回周杰伦五首并保留点歌。
- 两阶段按实际曲长交付，分别报告覆盖时长；没有为了默认 24 首硬凑。
- 严格纯音乐仅接受有歌曲级证据的候选，出现只能交付 1–2 首的情况；未知语种/人声时返回不足或零首，不冒充满足要求。
- 测到了上游 502、超时和模型不可用时的回退。一次异常等待促成了执行器超时竞速修正，并有不响应 AbortSignal 的测试覆盖。
- 成功样本中曾观察到约 4–9 秒的普通推荐；这些是少量联调样本，不能代表稳定 p95。性能门槛仍未验收。

运行显式真实联调（会调用已配置模型，消耗相应额度）：

```sh
npm run check:recommendation:live
# 只查第 3 类，或第一类
node scripts/check-recommendation-live.mjs --case=3
node scripts/check-recommendation-live.mjs --one
```

脚本只读真实偏好，不写喜欢、屏蔽或实际播放会话；证据放在 `data/live-checks/`。普通 trace 放在当前账号的 `data/accounts/<accountKey>/recommendations/`。密钥、Cookie、签名播放 URL 不写入 trace；这些数据目录均被 Git 忽略。
