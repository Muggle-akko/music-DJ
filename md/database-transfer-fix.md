# 数据库传输修复与计量（2026-10-16）

## 已确认的问题

Neon 项目控制台显示本期数据库出站传输 12.31 GB、逻辑存储约 41.77 MB、计算约 0.52 CU-hr，并明确提示月度网络传输额度耗尽。云端因此在数据库初始化时失败，返回 HTTP 500。不能把 12.31 GB 当作音乐流量，也不能声称已精确归因到每个接口。

源码中确认的放大路径：

- 每次云端 API 请求重新选择账号状态时，会先下载旧 `state.json`，即使账号专属状态早已存在。
- 每次请求清空反馈缓存；随后 snapshot 读取反馈时重新下载反馈快照、扫描历史 JSONL，并重新保存快照。
- 文件式存储的备份实现是 `SELECT body` 下载旧内容，再上传备份；云端临时 JSON 文件再改名也增加了写放大。
- 所有 API 在请求前后读写 `cloud-runtime.json`；运行状态混入完整歌曲检索记录，使浏览器和 Agent 心跳也搬运搜索结果。

## 实现

- 数据库读取携带本机缓存的行版本；版本未变仅返回版本号，不再返回整块内容。64 MB 有界缓存只保存不可变字节，调用者得到独立 Buffer/解析对象。跨实例写入、删除、回滚由数据库版本检查处理，不采用可能掩盖更新的固定 TTL。
- 账号状态存在时直接选择账号路径，跳过旧资料迁移读取。
- 反馈缓存根据 `feedback.json` 数据库版本失效。数据库中的日志追加与反馈快照同事务提交，因此同日已完成维护的快照无需重复回放日志；本地文件模式继续保留崩溃恢复逻辑。
- 备份使用数据库内部 `INSERT … SELECT`；JSON 在事务中直接替换目标行；相同内容不更新行版本。
- 大 JSON 写入时附带压缩副本。原始 `body` 保留原 JSON 格式，旧数据无需全量转换，旧写入仍可读取。新代码验证压缩副本与原文校验值一致才使用它；音频保持原样。两个可空列由受 schema advisory lock 保护的启动代码以 `ADD COLUMN IF NOT EXISTS` 添加，不重建原表。
- 检索凭据拆到 `agent-lookups.json`，只在 Agent 工具调用时加载/保存；心跳运行状态不再带歌曲检索结果。旧的混合运行状态在同一事务中迁移引用。跨版本回滚后可能需要 Agent 重新检索，但原 JSON 资料仍可被旧程序读取。

## 计量方法

`scripts/measure-db-transfer.mjs` 只接受回环 PostgreSQL URL，创建独立数据库，结束后删除测试库。TCP 代理计数实际 PostgreSQL 协议两方向字节，计量不依赖 SQL 查询次数猜测。

使用本机账号资料副本（约 1,378 首收藏、约 300 KB 反馈、约 1.2 MB 当日日志），清空测试队列、推荐和电台列表；登录改为本地网易云桩，不访问真实网易云账号或音频。副本仅写入本地临时数据库。

模拟 60 轮、每轮代表 5 秒：播放器 heartbeat + snapshot；每三轮 Agent heartbeat + 一次 progress 反馈。实际加速执行，模拟 5 分钟后折算每小时。初次登录/暖机的字节不计入稳态。

| 版本/场景 | 5 分钟 DB → 应用 | 折算 DB 出站/小时 | 应用 → DB/小时 |
| --- | ---: | ---: | ---: |
| 修复前，两个实例交错 | 268,521,780 B | 3,222.26 MB | 383.39 MB |
| 修复后，两个实例交错 | 3,288,171 B | 39.46 MB | 98.91 MB |
| 修复后，单实例 | 345,980 B | 4.15 MB | 98.83 MB |

两个实例场景出站减少约 98.8%。应用入站写入量仍有优化空间；Neon public network transfer 的计费口径是数据库出站，不应混成双向总量。参考官方说明：https://neon.com/blog/how-to-make-the-most-of-neons-free-plan 。

相同负载每天 2 小时、30 天：约 0.25–2.37 GB/月；每天 4 小时：约 0.50–4.74 GB/月。**仅这条同步链路**，首次拉取收藏画像、搜索/创作、大队列变更、更多设备/实例、频繁冷启动和不同数据规模额外计算，不承诺始终落在免费额度内，也不是云端恢复后的真实账单。

复现（需自备临时本地 PostgreSQL；不要填写生产库）：

```sh
AWUDIO_TEST_DATABASE_URL='postgres://...@127.0.0.1:端口/测试管理库' \
AWUDIO_BENCH_INSTANCES=2 AWUDIO_BENCH_DATA_DIR=data \
node scripts/measure-db-transfer.mjs /私有临时目录/修复前源码
```

省略最后的源码路径仅测当前版；省略 `AWUDIO_BENCH_DATA_DIR` 使用合成夹具。脚本不输出 Cookie/Agent token 或资料内容。

125 项测试通过，0 跳过，使用本地 PostgreSQL。覆盖双实例队列、反馈、检索凭据拆分与旧格式迁移、冷启动、失败 COMMIT 不返回成功、外部写入缓存失效、旧写入后压缩副本失效、备份和 Buffer 隔离。

## 第二轮：浏览器缓存、低频同步与资料备份

- 浏览器使用按网易云账号隔离的 Cache Storage；仅在成功完成账号读取后启用。退出登录或服务器要求重新登录时清理，不能用缓存替代认证。最多 40 项/约 4 MB，单项 512 KB；缓存失败不会阻止在线请求。
- 歌单与歌单分页缓存 5 分钟、搜索 1 分钟、历史电台 2 分钟；手动刷新强制走网络。推荐仅缓存歌曲资料，按创建时间保留最多 3 天；不缓存操作指令、令牌、音源或凭据。队列继续使用已有的设备本地回退与服务器 revision 冲突检查。
- 推荐与收藏反馈使用独立内容版本：未变化时快照省略对应大数组，播放指令和租约仍照常返回。收到新内容后才更新推荐缓存。
- 播放器同步策略：Agent 在线前台 5 秒、后台 10 秒；无 Agent 正在播放时 30 秒，无 Agent 暂停或后台播放时 60 秒；后台暂停且无 Agent/待回执时停止轮询，回到前台立即检查。断网失败逐步退避，最多 120 秒；手动刷新及恢复网络可主动检查。
- 低频心跳的设备在线窗口、控制租约和指令有效期同步调整，最长约 70 秒指令窗口，保留设备、generation、播放会话、队列 revision 和幂等回执检查。Agent 刚恢复时可能等待下一次低频检查，点刷新连接状态可主动检查；不能承诺后台浏览器随时执行指令。
- MCP 仅在音乐工具调用后的 5 分钟内发送 15 秒心跳，空闲后停止；下次工具调用检查会话时效，必要时安全地重新注册，不重试可能已送达的写操作。此脚本改动需要重新启动 MCP/Codex 才会加载。
- 设置页新增手动“下载资料备份”，包含账号原始状态（所有设备队列、推荐/电台/偏好）、收藏画像、反馈快照及歌曲特征。白名单排除 Cookie、浏览器会话、Agent 密钥、原始收听日志和音频文件。云端快照与日志同事务提交；快照包含持久反馈。下载只有数据库可读时可用，不是当前超额旧库的救援导出。网页备份限制 6 MB；没有自动定时任务，恢复工具尚未加入。

验证：130 项测试通过，0 跳过，包含真实本地 PostgreSQL。隔离浏览器实测歌单请求：首次 1 次 → 刷新页面重新打开仍 1 次 → 点手动刷新变为 2 次。备份下载入口已在隔离账号上验证。当前 Neon 仍被额度限制，新增策略的生产月用量不能直接沿用第一轮测量再承诺比例。
